# DeskTodo 0.2 设计说明

## 调研与取舍

- [PaperTodo](https://github.com/snownico0722/PaperTodo)：参考其以纸张承载待办、直接编辑和勾选的交互，将待办纸嵌入便签文档。未复制该项目的实现或资源。
- [Tiptap Markdown](https://tiptap.dev/docs/editor/markdown/getting-started/basic-usage)：采用 ProseMirror / Tiptap 的单一文档、输入规则、选区和撤销系统，实现同一表面中的编辑与排版。Markdown 用于持久化与剪切板交换，编辑时允许规范化排版语法。
- 本仓库 `APIConfig/src-tauri/src/data.rs`、`DeskFinger/src-tauri/src/store.rs`：参考「配置仅存路径、数据独立于安装目录」的方式，并增加写入排序、原子替换和上一份快照。
- 本仓库 APIConfig / DeskFinger 界面：延续暗蓝背景、克制的渐变、圆角卡片和细描边。正文使用 17px，待办内容 16px，默认界面文字 14px。

## 文档与交互

左侧只承担夹选择；横向标签只显示便签标题，便签页占据主体。不设预览卡、独立快捷菜单按钮或固定提示卡。便签切换使用短促的淡入和位移动画，尊重系统减少动态效果设置。

Markdown 即时编辑由 `src/editor/NoteEditor.tsx` 负责，支持常见 GFM 内容、表格、普通任务列表与本地公式渲染。源码切换保留为检查与精细修改入口；它不是默认编辑流程。不执行原始 HTML 脚本或任意插件代码。

slash 菜单只响应正文空段落中实际键入的 `/`，位置由编辑器选区坐标计算。粘贴、链接中的斜杠和代码块内容不会打开菜单。菜单打开时继续输入即关闭，避免遮挡正常写作；组合输入期间不拦截按键。

待办纸是语言标记为 `todo` 的代码块 NodeView。每次行操作都提交回同一个编辑器文档，从而参与撤销、保存和 Markdown 复制。空待办行不会因内容为空而消失，非任务行作为注释保留；清除已完成只作用于当前块。

## 扩展方式

`src/editor/blocks.tsx` 的 `blockPlugins` 是编译期扩展注册表，每项包含：

- `id`：Markdown 围栏语言名。
- `label` / `description` / `symbol`：slash 菜单的显示信息。
- `initial`：插入时的初始文本。
- `View`：接收 `text`、`replace`、`remove`、`undo`、`redo` 的 React 组件。

新增块时实现组件并注册即可，共用 Markdown 保存和 slash 菜单。公式转换或翻译服务可作为新组件/命令接入；当前版本没有网络翻译或模型调用。注册表不是第三方运行时插件安装器。

普通代码块由同一个扩展保留语言和内容。序列化选择比内容中的反引号更长的围栏，避免待办文字中出现三反引号时破坏文档。KaTeX 设置 `trust: false`，资源随程序打包。

## 保存与恢复

前端使用保存队列合并尚未开始的连续更新、串行提交；成功状态只对应最新快照。切换目录先等待队列完成，再载入新工作区；即使目标目录复用了相同便签 ID，也会重建编辑器。

Rust 端对每次目录操作加锁、校验结构及 ID，并在保存时检查调用所携带目录是否仍是当前目录。既有文件损坏、目录消失或格式错误会显式报错；空目录才可初始化。配置路径仅在目标数据准备成功后更新。

应用数据与图标、安装目录解耦。初始化仅一个收件箱和一张便签；旧版 localStorage 内容优先迁移，原缓存保留。浏览器预览单独使用缓存，不冒充桌面文件存储。
