# APIConfig 交互与实现设计

## 主任务与布局

主任务是“选一个 API 来源，应用到指定配置目录”。Codex / Claude 保留独立场景，采用固定双栏：左侧紧凑 Provider 列表，右侧目标配置卡片。左右列表独立滚动，面板标题和操作提示固定，避免来源越来越多时把应用按钮推到整页底部。

默认窗口 1180 × 800；最小桌面窗口 920 × 620 下仍可同时看到来源与目标。宽屏目标可排成两列，小屏按上下两块独立滚动区域显示。Provider 支持搜索，目标超过四个时显示目标搜索。

## 信息层级

1. 常驻：Provider 名称、服务域名、低干扰状态点；目标名称、路径、当前来源与应用按钮。
2. 选择来源后：目标面板顶部显示“待应用来源”，匹配的目标显示“已生效”。应用成功有短暂边框反馈和结果提示。
3. 按需查看：点击 `···` 打开右侧详情抽屉。连接、模型、额度独立折叠，编辑、删除、查询设置也放在抽屉内。详情不改变主界面尺寸和滚动位置。
4. 批量查询：点击“全选”展开操作条，查询范围是本场景全部 Provider，不使用逐卡复选框；搜索不会缩小“全选”的范围，操作条显示总数。全选不会改变待应用来源。

详情抽屉支持 Esc 关闭、焦点约束和关闭后恢复焦点。场景导航支持左右方向键、Home / End。主要控件有明确名称；状态除颜色外也有可访问文本和详情说明。

## 查询状态和启动行为

启动时对初始 Codex / Claude Provider 各执行一次连接检查。两个场景持续挂载，切换分页不会重复启动查询。只读 GET 模型接口用于检查连接与认证，不发起模型生成，也不自动发现模型或查 Provider 额度。

- 启动检查在后台异步执行，最多 3 个 HTTP 请求同时进行；不阻塞选择、应用、编辑或拖动。
- Provider 状态以小圆点和微弱边缘光晕表示，绿 / 红 / 黄分别对应可用 / 异常 / 部分可用；检查中轻微明暗变化。
- 模型与额度仍手动触发，支持单项和全场景批量。每项结果独立；缺接口、缺字段或个别失败不会阻塞其他任务或应用操作。
- 每个 HTTP 请求超时 12 秒，单次响应最多 2 MB。无轮询、无自动重试；“停止”只停止待执行任务，已开始任务正常结束。
- 编辑 / 删除 Provider 或保存查询设置时使该条目的旧查询失效。迟到的旧请求不会重新覆盖新状态，尚未启动的旧任务直接跳过。
- 手动查询失败时保留最后一次可用数据，明确标记旧结果与原查询时间。数据只保留在本次应用会话。

连接成功代表模型列表接口可访问并返回正确结构，不代表生成能力已经验证。详情保留这个边界说明。

## 整卡排序

直接拖动 Provider 或目标卡片，无常驻拖动手柄。卡片按钮、输入框与菜单不会启动拖动；拖动释放也不会误触选择或应用。拖起时轻微缩放 / 淡化，目标位置显示细插入线，顺序变化采用短位移动画。

动画只用于同一批卡片的实际重排，不用于搜索、查询状态更新和分页切换，避免卡片短暂叠放。系统开启减少动态效果时停用动效。聚焦卡片后 `Alt + ↑ / ↓` 可完成键盘排序。

搜索过滤期间禁用排序，避免把部分列表当成完整排序写回。后端仍校验完整、无重复的名称列表，四个列表分别保存顺序。

## 模型与 Provider 额度

模型从 `data[].id` 读取 ID、可选 `display_name` 读取显示名称，支持搜索。Claude 场景支持 `has_more` / `last_id` / `after_id` 分页，最多读取五页，后续页失败保留已有结果。

额度适配保持已有功能：

| 适配器 | 行为 |
| --- | --- |
| 未配置 | 不请求网络，批量查询直接跳过 |
| Kimi Code | 解析周额度、5 小时窗口、会员等级、重置时间 |
| 自定义 | 按 JSON Pointer 映射余额、已用、总量、剩余、重置时间；数值字段支持数字或数字字符串 |

默认模型与 Kimi 额度路径分别补齐 `/v1/models` 与 `/v1/usages`，不重复已有 `/v1`。支持同源自定义 GET 路径、Bearer / x-api-key / 无认证。禁止跟随重定向；错误不回显完整响应或密钥。

## Kimi 独立分页

Kimi 分页的主任务是查看订阅额度，不参与 Provider → Home 应用流程。

- 两张额度卡片分别展示周额度、5 小时窗口；环形进度表示剩余比例，明细展示已用、总量、剩余、重置时间。
- 缺少总量或剩余值时不猜测百分比；缺少字段显示 `—`。不把缺失视作零额度。
- 首次进入页面自动查询一次，后续切回保留结果，手动刷新更新；失败显示原因并保留上次可用数据。
- 账号设置支持手动输入和从 DeskBot 本地 JSON 导入。导入只复制服务地址与 Key，不改源文件、不复制 DeskBot 的聊天与工作区设置。
- 配置在应用数据目录 `kimi.toml` 的 `[account]`，不在源码；IPC 仅返回名称、地址、掩码和已配置状态。编辑 Key 留空保留原值。
- 账号变化后清除旧额度并立即刷新新账号，防止不同账号的数据混用。

## 实现入口

- `App.tsx`：三场景导航；Codex / Claude 保持挂载以保存查询状态。
- `ScenePanel.tsx`：双栏布局、全选查询、来源应用、详情与管理。
- `ProviderCard.tsx` / `TargetCard.tsx`：紧凑来源和目标卡片。
- `SortableList.tsx`：整卡拖动、键盘排序、重排动画。
- `useInspections.ts`：一次启动检查、查询队列、版本失效与停止队列。
- `KimiPanel.tsx` / `src-tauri/src/kimi.rs`：Kimi 额度界面、账号持久化和 DeskBot 导入。
- `inspection.rs`：共用的 HTTP、模型分页与额度解析。

现有 Codex / Claude 配置写入和本机数据目录保持兼容。本轮不引入自动批量应用、后台轮询、备份管理功能、密钥库、启动器或系统托盘。旧配置迁移时仅归档原始文件以便恢复。

## 验证边界

浏览器测试用模拟 IPC 覆盖启动期间应用、双栏滚动、最小窗口、全选查询、详情搜索 / 重试、Esc、整卡拖动、键盘排序、旧请求失效、Kimi 刷新与账号编辑。Rust 测试覆盖既有配置逻辑、HTTP 与解析，以及 Kimi 导入与脱敏。真实 Kimi 额度接口另以本机配置执行只读查询验证，不将真实 Key 或额度响应写入测试样例。


## 数据目录与文件布局

右上角“数据目录”打开设置弹窗，显示当前路径和四个场景文件的用途；可打开文件管理器、选择本地文件夹或输入绝对路径。默认选“复制当前配置”，带上四个分页的数据与凭据，旧目录保留。若目标含已有配置，则拒绝覆盖；用户可改选“使用已有配置”。切换完成后刷新所有场景与查询结果，旧查询队列停止。目录不可用时，加载错误页仍提供目录选择入口。

- `codex.toml`：`version`、`homes`、`providers`；Provider 内含 `color` 与 `inspection`。
- `claude.toml`：同样的分层与命名，各场景独立存储。
- `kimi.toml`：`version`、`account.name`、`account.url`、`account.key`。Key 可在 Kimi 账号设置中编辑，空值表示保留已有 Key。
- `apis.toml`：`version` 与 `[[accounts]]`，包含独立 API 的兼容地址、Anthropic 消息地址、Key 和身份色。
- 默认应用配置目录内的 `storage.json`：仅记录选择的数据目录；未选择时沿用默认目录。

旧数据先验证全部结构，再生成新文件并把原文件归档到 `legacy-backup/`。配置更新采用临时文件替换，目录指针最后写入；迁移错误不包含配置正文或密钥。复制保留来源数据，已有目标配置不会被覆盖。

## Provider 身份与应用状态

自动为来源分配一组低饱和颜色，存储到配置，因此排序与改名不会漂移。来源头像和已使用它的目标图标、侧边细线、当前来源名称保持同色；来源旁显示已应用目标数。待应用栏使用所选来源的颜色及生效计数，目标上的颜色始终来自当前实际配置。

选中来源后，仅已经匹配该来源的目标显示缓慢的光晕和扫光；取消选择即停止，应用成功会短暂增强反馈。无匹配目标保持中性底色。连接检查状态仍独立显示，应用状态有名称与“已生效”文字，不能只依靠颜色辨识。系统要求减少动态效果时停止所有动画。
