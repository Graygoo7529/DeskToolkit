# APIConfig 交互与实现设计

本次实施保留 Codex / Claude 场景分页，以及 Provider 应用到 Home 的主要布局。连接、模型和额度都是 Provider 的子项，不新增独立概览或模型页面。

## 页面与操作

每个场景上方为 Provider 网格，下方为 Home 列表。两种选择相互独立：

| 操作 | 作用 | 是否修改 Home |
| --- | --- | --- |
| 点击 Provider 名称或卡片空白处 | 选择单个待应用 Provider，高亮卡片 | 否 |
| 勾选 Provider / 全选 | 设置本场景的批量查询范围 | 否 |
| 点击工具栏查询按钮 | 对已勾选 Provider 执行对应查询 | 否 |
| 点击“检查三项” | 每个选中 Provider 分别执行连接、模型、额度查询 | 否 |
| 展开连接 / 模型 / 额度 | 查看结果或单独重试 | 否 |
| 查询设置 | 为该 Provider 配置模型路径、认证与额度适配 | 否 |
| 在 Home 上点击“应用” | 执行原有 URL / Key 写入操作 | 是 |
| 拖动 ⠿ 或聚焦手柄按上下键 | 保存所在列表的顺序 | 否 |

无勾选时禁用批量查询按钮。不同场景的勾选、待应用项、展开状态、搜索和结果分别保留。卡片中的勾选、展开、查询、编辑、删除与拖动均不会触发待应用项切换。

查询期间暂时禁止编辑、删除和重排该场景的 Provider，以避免请求结果归属错误；Home 的应用和管理仍然可用。原有查询配置在编辑 Provider 名称或密钥时保留，旧结果在成功编辑后失效。

## 查询状态

每个 Provider 的三项查询各自有状态：未查询、排队中、查询中、成功、部分可用、失败、已跳过。

- 统一请求上限为 3 个并发；页面逐项更新结果和批次统计。
- 每个请求最多等待 12 秒，单个响应最多 2 MB；没有自动重试和轮询。
- 一项失败不取消同批次其他项；没有额度适配器时直接跳过，不请求网络。
- “停止待执行项”停止后续排队任务，已开始的请求结束后显示完成数和取消数。
- 查询失败时保留最后一次可用模型 / 额度，标记旧结果及原查询时间，避免把旧余额误认为本次数据。
- 查询结果只保留在当前应用会话；应用重启后恢复未查询状态。

## 连接与模型

连接检查对模型接口执行只读 GET，检查 HTTP 状态、JSON 和模型列表结构。成功只说明该接口可访问并符合列表格式，不能证明任意模型可生成，也不验证上下文长度或模型能力。

模型发现从 `data[].id` 读取模型 ID，从可选 `display_name` 读取显示名称；列表可搜索。空数组是有效结果，缺少 `data` 数组是错误，部分条目缺失 ID 时保留其余模型并标记部分可用。

Claude 场景识别 `has_more`、`last_id` 并用 `after_id` 翻页，最多 5 页；缺少或重复游标、到达上限、后续页失败时保留已有模型。其他分页协议不推测处理，服务明确返回更多分页时标记部分可用。

模型接口路径可选，默认在 Base URL 之后补齐 `/v1/models`。认证支持 Bearer / x-api-key / 无认证；Claude 模型查询附带 `anthropic-version: 2023-06-01`。

## 额度适配

| 适配器 | 请求 | 展示 | 缺损处理 |
| --- | --- | --- | --- |
| 未配置 | 不请求 | 未配置 / 已跳过 | 不影响模型、连接或应用 |
| Kimi Code | Base URL 补齐 `/v1/usages`，可自定义路径 | 周额度、5 小时窗口、会员等级、重置时间 | 数值字段独立解析；缺失显示 — |
| 自定义 | 用户填写同源 GET 路径 | 余额、已用、总量、剩余、重置时间、单位 | 至少配置一个数值 JSON Pointer；只展示可识别值 |

Kimi Code 的字段与解析方式参考 `DeskBot/src-tauri/src/quota.rs`，但不引入 DeskBot 的定时轮询、托盘或独立额度页面。数字字符串和数值都可解析；0 与缺失严格区分。单位由用户设置，不自动推断币种、不换算余额。

自定义字段示例：`/data/balance`、`/data/used`、`/data/limit`、`/data/remaining`、`/data/reset_at`。重置时间支持 ISO 字符串；数组字段可使用 `/data/0/balance`，特殊键使用 JSON Pointer 的 `~0` / `~1` 转义。

查询复用 Provider 密钥，不增加第二套账号。不同管理凭据、跨域、POST、Cookie 登录、脚本解析不在本次适配范围。

## 文件与数据

- `src/components/ScenePanel.tsx`：两个场景复用相同布局和查询交互。
- `src/components/ProviderInspection.tsx`：Provider 三个查询子项、搜索、缺损值和旧结果提示。
- `src/useInspections.ts`：手动批次、三并发、独立错误与停止队列。
- `src/components/SortableList.tsx`：独立手柄拖动和键盘排序。
- `src-tauri/src/inspection.rs`：认证、同源请求、模型分页、Kimi / 自定义解析。
- 旧 Provider 自动填充 `inspection` 默认值；查询配置随 Provider 保存，Home 不保存任何额度 / 模型数据。
- 四个列表独立排序，后端验证排序提交包含完整、无重复的现有名称后写入，拒绝陈旧列表覆盖。
- 项目目录更名为 `APIConfig`，根 README 和 CI 路径同步；应用 identifier 保持兼容。

## 本次范围

本轮只实现手动连接检查、模型发现、额度适配 / 查询和 Provider / Home 排序。移除旧路线图中应用预览与备份撤销、Credential Manager / DPAPI、概览页、批量应用、快捷启动和系统托盘的实施计划。

## 验证

Rust 测试覆盖旧数据兼容、排序校验、默认地址与同源限制、Kimi 和自定义缺损解析、模型结构、HTTP 认证、分页失败保留数据、重定向拒绝与错误脱敏。

浏览器测试用固定模拟数据验证手动触发、批量选择与待应用分离、部分失败、模型搜索、旧结果提示、场景切换、Provider / Home 拖动及顺序保存、额度设置、两种场景应用和停止队列。真实服务的返回格式与权限仍以用户手动查询结果为准。

接口参考：[Claude API 概览](https://platform.claude.com/docs/en/api/overview)；Kimi 字段以同仓库 DeskBot 的已有实现为依据。
